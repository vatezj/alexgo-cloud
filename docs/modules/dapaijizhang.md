## 1. 项目概述

### 1.1 产品定位
开发一款微信小程序，用于**线下打牌娱乐时的纯分数记账**。只做分数的记录、统计与房间内多人实时同步，**不涉及金钱、不提供任何资金结算**。这是产品红线，也是小程序审核的合规前提。

### 1.2 项目目标
1. 实现开房、扫码/转发邀请好友进房、房间内实时记分与语音播报。
2. 实现茶饭（抽水）两种设置方式：自动百分比抽水、手动 DIY 数值。
3. 实现房间结算、个人退房、历史战绩、好友排名与拉黑。
4. 实现「设置总分（单局输分上限）」，防止一局累计输分失控。
5. 保证多设备实时同步，弱网可下拉刷新、断线可恢复。
6. 支持房主转让，保证开房人中途离场时房间可继续。
7. 上线 V1.0，后续迭代「战绩自定义统计」等高级功能。

### 1.3 目标用户与角色

| 角色 | 说明 | 关键权限 |
|---|---|---|
| 游客 | 未授权微信信息 | 仅浏览首页、使用手册 |
| 普通玩家 | 已授权，可开房/进房 | 记分、支出、退房、查看战绩 |
| 开房人（房主） | 房间创建者或受让者 | 修改茶饭/总分配置、结算、转让房主、关闭房间（**无踢人权限**） |
| 系统 | 定时任务、WebSocket 服务 | 超时关房、广播、快照兜底 |

### 1.4 术语表

| 术语 | 定义 |
|---|---|
| 分数 | 房间内记账的纯数字，不代表任何资金 |
| 茶 / 饭 | 房间**公共池**积分，模拟「请喝茶吃饭」，**非抽成、非资金、非个人收支** |
| 会话（局） | 从玩家进入房间到退房/结算/房间关闭的一次完整周期，用于**累计输分统计**；中途退房再进房 = 新会话 |
| 把（笔） | 一次支出记账事件（提交一次「支出分数 + 茶饭」），用于**「从下把生效」** |
| **从下把生效** | **通俗解释**：房间进行中改配置时，不改当前这一笔的算法；从**下一次有人提交支出**开始，才按新配置算。比如这把手动记了 10 分，改完百分比后，这 10 分仍按旧比例，下一笔才用新比例。实现上用「待生效字段」暂存，下一笔支出时刷入生效 |
| 快照 | 服务端房间当前全量状态，以服务端为准 |
| 上限提醒 | 某玩家会话累计输分达到 `max_lose_score` 时触发的全房提醒 |

> **「局/把」澄清**：累计输分按「会话（局）」统计；配置变更「从下把生效」指从**下一次支出记账（新的一把）**开始应用。

## 2. 合规要求（红线，必须全程遵守）

- 小程序**严禁任何赌博、资金相关描述**。全站文案统一为「**记账、计分工具，不涉及金钱，禁止用于违法行为**」，作为顶部提示栏常驻。
- 所有字段一律叫「**分数**」「**茶/饭**」，禁止出现「钱、赌注、下注、结算资金、抽成」等字眼。
- 「抽水」对外文案统一为「**请喝茶吃饭 / 茶饭设置**」的娱乐积分行为。
- 广告投放需控制位置（贴近功能按钮、减少误触），保留说明页解释。
- **代码变量、接口字段、数据库注释同样规避资金类命名**（`bet`/`cash`/`rake`），统一 `score`/`tea`。
- 提审前由产品 + 法务做一次文案全量扫描（见 12.3）。

## 3. 非功能需求（NFR）

| 类别 | 要求 |
|---|---|
| 性能 | 快照 P95 < 300ms；支出 P95 < 500ms；WS 广播 < 1s；单房间 ≤ 20 人 |
| 可用性 | 核心接口 ≥ 99.5%；WS 断线指数退避重连（最大 30s）；快照兜底最终一致 |
| 容错 | 息屏/断网重进提示刷新；下拉刷新显示「xx:xx:xx 刷新成功」；锁屏超 5 分钟重进弹确认 |
| 安全 | openid + token 鉴权；房间操作校验成员身份；幂等键防重放；配置仅房主可改 |
| 一致性 | 支出在 DB 事务内完成「分数 + 日志 + 累计输分 + 茶饭池」；WS 仅增量，**以快照为准** |
| 兼容性 | 基础库 ≥ 2.20；iOS/Android 主流机型；弱网可用 |
| 数据保留 | 房间日志 90 天；战绩快照长期（用户可删）；拉黑长期 |
| 可观测 | 在线房间、接口错误率、WS 连接数、上限提醒次数、茶饭池总额 |

## 4. 功能需求规格（FR）

### 4.1 首页模块
1. 微信授权头像昵称（底部入口可补授权）。
2. 【我要开房】【扫码进房】。
3. 展示：好友排名、总积分、赢/输场次、胜率、战绩入口。
4. 底部：客服、获取头像昵称、使用手册。
5. **验收**：未授权展示默认头像+引导；授权后刷新；入口跳转正常。

### 4.2 房间模块
1. 创建房间：生成**房号 + 二维码**，支持转发邀请，扫码加入。
2. 展示：玩家头像/昵称/实时分数、**茶饭公共池**、流水日志（记分、进出房提示）。
3. 提示：「点击好友头像可直接支出；点击自己头像可设置开关、昵称、退出」。
4. 弱网：下拉刷新、「xx:xx:xx 刷新成功」、断网提示、锁屏重进确认刷新。
5. 生命周期：无操作 **2 小时自动关闭**。
6. 房号 4 位字母数字，全局唯一，冲突重试；二维码含 `room_code` + 场景值。
7. **验收**：扫码/房号进房；重复进房幂等；非成员拒绝；已关闭房间拒绝并提示。

### 4.3 计分 & 支出模块
1. 支出弹窗：填写「支出分数」+「茶/饭」数值。
2. 提交后 WS 实时同步全员分数。
3. 支出数字角标提示待处理记录。
4. **记账口径**：
   - 支出方（输家）`cur_score -= 支出分数`，`cum_lose_score += 支出分数`；
   - 接收方（赢家）`cur_score += 支出分数`；
   - 茶饭按 4.4 规则进入**房间公共池**；
   - **茶饭不计入 `cum_lose_score`**。
5. **幂等**：携带 `client_request_id`，后端去重。
6. **并发**：房间级锁 + 乐观锁 `version`，串行化支出。
7. **验收**：A 记分后 B/C 1s 内更新；重复提交不重复扣分；并发后总分守恒。

### 4.4 茶饭设置模块（V1.2：房间公共池）

1. 入口：房间内点击「茶/饭」弹出配置层。
2. 配置项：**目标金额** + **抽取百分比**；目标金额 > 0 时开关开启。
3. 方式一（自动）：百分比 > 0% 时，每笔支出按 `T = round(支出分数 × 百分比)` 计算茶饭，**进入房间公共池**。
4. 方式二（手动 DIY）：左下角「支出」按钮直接录入数值记为茶饭，进入公共池。
5. **生效规则**：「本设置将从下把开始生效」——当前这把用旧配置，下一笔支出用新配置。
6. **公共池模型（V1.2 确认）**：
   - 房间维护 `tea_pool_total`（公共池累计）；
   - **默认记账方式（总分守恒）**：输家扣 `S`，赢家得 `S - T`，公共池 `+T`；
   - 手动 DIY：操作人指定来源玩家，从其分数扣 `T` 进池；
   - 房间页展示「茶饭公共池：X 分」；结算时公共池**仅供参考，线下自行处理**；
   - `tea_target_amount > 0` 且 `tea_pool_total >= target` 时：**自动关闭自动抽取开关**，写日志 + 提示，不再继续抽。
7. **验收**：百分比四舍五入整数；公共池累计正确、总分守恒；达标自动关闭并提示；手动 DIY 进池；「从下把生效」不影响当前把。

> 待确认细节：自动模式下茶饭来源（从赢家所得扣 / 输家额外扣 / 凭空记入）。**默认按「从赢家所得中扣除、总分守恒」实现**，评审时最终敲定。

### 4.5 设置总分（单局输分上限）

| 子项 | 设计 |
|---|---|
| 入口 | 「茶/饭」设置弹窗内并列「茶饭设置 + 总分设置」两个 Tab；创建房间可预填默认值 |
| 配置项 | `max_lose_score`（整数），0 = 不限制；支持「从下把生效」 |
| 计算口径 | 本**会话**某玩家累计输分 `cum_lose_score`（仅支出方扣分累计，**不含茶饭**） |
| 触发行为 | ① 写 `room_log(type=6)`；② 全房语音播报；③ 该玩家头像高亮/角标；④ WS 广播 `max_lose_alarm` |
| 后续动作 | **不强制拦截**，可继续记账或退房结算 |
| 清零条件 | 结算、退房、房间关闭；**中途退房再进房重新计算**（V1.2 确认） |
| 修改权限 | 房主可改，从下把生效；历史触发记录保留 |
| 触发频控 | 同一玩家同一会话**首次达上限全房提醒**；之后超限**仅写日志 + 个人轻提示**，不重复全房播报 |
| 多玩家触发 | 各自独立，按触发顺序广播 |

**验收**：上限=50，累计达 50 全房收到日志+语音+高亮；可继续记账；退房重进清零；「从下把生效」不影响当前把；频控生效。

### 4.6 语音模块（V1.2：偏好本地缓存）

1. 语音分：娱乐语音、流水、其他房间动态。
2. 开关：点击个人头像 → 弹窗 → 右侧语音图标 → 5 档循环。
3. 默认：进房「操作播放」；开房人默认全开。
4. **5 档状态表**：

| 档位 | 娱乐 | 流水 | 操作（进出/结算） |
|---|---|---|---|
| 全部关闭 | ✕ | ✕ | ✕ |
| 全部播放 | ✓ | ✓ | ✓ |
| 娱乐关闭 | ✕ | ✓ | ✓ |
| 流水关闭 | ✓ | ✕ | ✓ |
| 操作播放 | ✕ | ✕ | ✓ |

5. **V1 偏好仅本地缓存**（`wx.setStorage`），不做服务端同步；换设备不同步，V2 再评估。
6. **验收**：5 档切换正确；默认正确；切后台回前台状态保持（本地）。

### 4.7 结算、退房、战绩模块

1. 结算页：胜负文案、总计、未结状态、调侃文案；结算策略**仅供参考，线下自行处理**。
2. 退房：**仅本人操作，无踢人**；结算后点头像退出；数据为零可直接退房。
3. **开房人退房（V1.2 确认）**：弹确认「退房将自动结算房间」→ **自动触发结算** → 房主退房；若房内还有其他玩家，房间进入已结算只读态，其他玩家可自行查看/退房。
4. **数据为零退房（V1.2 确认）**：**生成空战绩**（record 快照写入，明细为 0）。
5. 战绩列表：首页入口，时间倒序；单条明细（各玩家分数、茶饭）；左滑看流水、排行、删除。
6. 好友排名页：左滑删除/拉黑；参与/不参与切换；可清零战绩。
7. 结算后 `status=1`，禁止记分；未结算玩家可留房查看或退房。
8. **验收**：快照与实时一致；房主退房自动结算；零数据生成空战绩；退房后从列表移除。

### 4.8 好友模块
1. 好友排名、删除、拉黑、参与/不参与切换。
2. 拉黑后不可再邀请/被邀请进同一房间。
3. **验收**：拉黑后排名不可见；切换后列表刷新。

### 4.9 辅助模块
1. 使用手册：结算/退房/历史、茶饭设置、语音、好友排名、广告说明、重要提示。
2. 客服留言：微信客服，24h 回复。
3. 广告位：补贴成本，贴近按钮减少误触，说明页解释。
4. 网络容错：断网提示、下拉刷新、重进恢复。
5. **验收**：手册完整可滚动；客服可达；广告不遮挡核心按钮。

### 4.11 转让房主（V1.2 新增）

**需求说明**：开房人中途有事需要离场，但房间还要继续，可把「房主」身份转给房间内其他成员，保证配置修改、结算等权限不丢失。

| 子项 | 设计 |
|---|---|
| 入口 | 点击自己头像（房主）→ 设置弹窗 →「转让房主」→ 选择房内成员 → 二次确认 |
| 权限 | **仅当前房主**可发起；目标必须是**当前房间内成员**；结算后/关闭后不可转让 |
| 交互 | 选择成员 → 提示「转让后你将变为普通玩家，房主权限交由对方」→ 确认 |
| 生效 | 立即生效；`room.creator_id` 更新；`room_user.is_creator` 旧房主置 0、新房主置 1 |
| 通知 | WS 广播 `transfer_owner`；全房语音/文字提示「XX 已成为新房主」；写 `room_log(type=9)` |
| 边界 | 转让后原房主仍是普通玩家可继续记分；新房主获得配置/结算/再转让权限；不可转让给已退房/拉黑成员 |
| 是否需对方确认 | V1 简化：**直接转让 + 通知**（不做对方确认弹窗）；如产品要求双向确认，V2 再加 |
| 验收 | 转让后权限即时切换；日志与广播正确；非房主无入口；结算后不可转让 |

## 5. 关键业务规则与流程

### 5.1 房间生命周期状态机
```
[创建] → status=0 进行中
   ├─ 结算（房主手动 / 房主退房自动）→ status=1 已结算（禁记分，可查看/退房）
   ├─ 超时（无操作 2h）→ status=2 已关闭（只读，定时清理）
   └─ 全员退房 → status=2 已关闭
```
- 「无操作」：无支出/进房/退房/配置变更；心跳/刷新不计。
- 状态流转写 `room_log(type=8)` 并广播 `room_status`。

### 5.2 「从下把生效」数据模型（通俗版 + 技术版）

**通俗解释**：房间打到一半，房主改了茶饭百分比或输分上限。为了不跟已经算完的那一笔打架，**改完不马上生效，等下一次有人提交支出时才开始用新配置**。当前这一笔继续用旧配置。

**技术实现**：
- `room` 增加待生效字段：`pending_tea_target_amount`、`pending_tea_percent`、`pending_max_lose_score`、`pending_apply_round_no`。
- 修改配置：写 `pending_*`，`pending_apply_round_no = 当前把序号 + 1`。
- 每次支出提交：若 `pending_apply_round_no <= 当前把序号`，把 `pending_*` 刷入生效字段并清空 pending。
- 当前把用旧配置，下一把用新配置。

> 若产品后续希望「从下一会话生效」，改为 `pending_apply_session_no`；**V1 默认按「下一笔支出」实现**。

### 5.3 支出与茶饭记账流程（事务内）
```
1. 鉴权：成员 + status=0
2. 幂等：client_request_id 已存在 → 返回上次结果
3. 加锁：房间级锁
4. 应用到期 pending 配置
5. 支出方 cur_score -= S；cum_lose_score += S
6. 接收方 cur_score += S
7. 茶饭：T = round(S × percent)（若自动开启且未达标）
   → 公共池 tea_pool_total += T；赢家实得 S - T（默认模型）
   → 写 room_log(type=2)
   → 若 tea_pool_total >= target：自动关闭自动开关，写日志+提示
8. 写 room_log(type=1, score, tea, from, to)
9. 上限判断：cum_lose_score >= max_lose_score 且 >0
   → 写 room_log(type=6)，标记触发（频控）
10. 提交事务
11. WS 广播 expense / tea_pool_update / max_lose_alarm
```
- 任一步失败整体回滚；广播失败不影响事务，靠快照兜底。

### 5.4 累计输分与上限
- 口径：仅支出方扣分累计，不含茶饭、不含赢分。
- 清零：结算/退房/房间关闭；**中途退房再进 = 新会话，重新累计**。
- 频控：首次全房，后续个人。

### 5.5 退房、结算、房主转让边界

| 场景 | 行为 |
|---|---|
| 普通玩家退房 | 移除成员，写 `room_log(type=4)`；不影响他人 |
| **开房人退房** | 弹确认 → **自动触发结算** → 房主退房；房间进入已结算只读态 |
| 结算后玩家 | 只读，可退房；不可记分 |
| **数据为零退房** | 允许，**生成空战绩快照** |
| **转让房主** | 仅房主、仅房内成员、结算前；立即生效 + 广播 + 日志；原房主变普通玩家 |

### 5.6 权限矩阵

| 操作 | 游客 | 普通玩家 | 开房人 | 系统 |
|---|---|---|---|---|
| 开房 | ✕ | ✓ | ✓ | — |
| 进房 | ✕ | ✓ | ✓ | — |
| 记分/支出 | ✕ | ✓ | ✓ | — |
| 修改茶饭/总分配置 | ✕ | ✕ | ✓ | — |
| 结算 | ✕ | ✕ | ✓ | — |
| **转让房主** | ✕ | ✕ | ✓ | — |
| 退房 | ✕ | ✓（本人） | ✓（本人，自动结算） | — |
| 超时关房 | ✕ | ✕ | ✕ | ✓ |
| 踢人 | — | ✕ | ✕ | ✕ |

## 9. 实时同步方案（WebSocket）

- 通道：`wx.connectSocket` + token 鉴权。
- 事件与负载：

| 事件 | 负载示例 | 说明 |
|---|---|---|
| `expense` | `{roomId, from, to, score, tea, curScores, version}` | 记分增量 |
| **`tea_pool_update` ★** | `{roomId, teaPoolTotal, autoEnabled}` | 公共池/开关变化 |
| `join` / `leave` | `{roomId, userId, nickname}` | 成员变更 |
| `settle` | `{roomId, settlementId}` | 结算 |
| `tea_config` | `{roomId, pending, applyRound}` | 配置待生效 |
| `max_lose_alarm` | `{roomId, userId, cumLose, limit, firstTime}` | 上限提醒 |
| `room_status` | `{roomId, status}` | 状态变更 |
| **`transfer_owner` ★** | `{roomId, oldOwnerId, newOwnerId, nickname}` | 房主转让 |
| `ping` / `pong` | — | 心跳 |

- **弱网策略**：息屏重进/下拉刷新拉快照；心跳 30s + 指数退避重连；**以快照为准**，客户端按 `version` 去重/丢弃过期；锁屏超 5 分钟重进确认刷新。
- **广播顺序**：同房间按事务提交顺序，客户端 `version` 单调校验。

## 12. 测试要点与验收标准

### 12.1 功能用例
1. 创建房间生成房号二维码，扫码加入；重复进房幂等。
2. 多设备同房，A 记分后其他设备实时刷新；并发总分守恒。
3. 百分比茶饭进**公共池**、总分守恒；手动 DIY 进池；目标金额达标**自动关闭自动抽取**并提示。
4. **总分上限**：上限=50，达 50 全房提醒；可继续；**退房重进重新计算**。
5. **「从下把生效」**：改配置不影响当前把，下一笔支出起生效（用实际数字验证）。
6. **上限频控**：首次全房，后续个人。
7. 房间 2h 无操作自动关闭；关闭后拒绝记分。
8. 本人可退房，无踢人；**房主退房自动结算**；**零数据退房生成空战绩**。
9. 断网/息屏重进下拉刷新正确；`version` 冲突以快照为准。
10. 战绩保存/明细/删除正常；快照与实时一致。
11. 语音 5 档切换正确；默认档位正确；本地缓存保持。
12. **转让房主**：房主可转让给房内成员；转让后权限即时切换、广播+日志正确；非房主无入口；结算后不可转让。
13. 权限矩阵逐项验证。

### 12.2 异常测试
重复提交（幂等）；并发支出（锁）；已结算/关闭后操作；非成员访问；弱网重连；锁屏超时刷新；转让给已退房成员被拒。

### 12.3 合规验收
全站文案扫描无禁用词；顶部提示常驻；茶饭为娱乐积分表述；代码/字段无资金命名。

### 12.4 性能验收
快照 P95 < 300ms；支出 P95 < 500ms；广播 < 1s；20 人在线稳定。
