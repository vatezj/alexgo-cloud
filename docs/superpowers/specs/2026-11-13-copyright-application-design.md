## 4. 方案取舍

| 方案 | 描述 | 取舍 |
|---|---|---|
| **A. 脚本生成（选定）** | python-docx 脚本产出两份 docx；源码文档按策划文件清单精确分页；手册 Markdown 驱动 + 截图嵌入 | 规格（页数/行数/页眉）机器保证；可重跑；前期要写脚本 |
| B. 我出稿、用户 WPS 手排 | 输出纯文本/图文稿，人工粘贴进 WPS | 灵活，但 60 页 × 每页行数与页眉全靠手核，受理规格易翻车 |

选 A 的核心理由：受理规格是**硬指标**（页数、每页行数、页眉三要素），脚本断言比人工核对可靠。

## 6. 源代码文档设计

### 6.1 分页规格（硬断言）

- 恰好 60 页：前 30 页 + 后 30 页。
- 每页恰好 50 行代码（整份文档最后一页允许 <50 行，但按 50 行设计就无需例外）。
- 页眉左：`alexGo-cloud 后台管理系统软件 V1.0`；页眉右（或页脚）：页码 `第 N 页 / 共 60 页`。
- 等宽字体（Consolas / Courier New），小四或五号，单倍行距，行数按"每页 50 行"反推字号。
- 每个文件起始处插入一行文件路径标注（如 `// ===== src/xxx/main.go =====`），便于审查时定位——此行计入 50 行配额。

### 6.2 文件清单编排（`file_manifest.py`）

顺序即叙事：**启动 → 配置 → 中间件与横切 → 核心 pkg → system 模块 → member → order → 前端 admin 关键文件**。

- **前 30 页（~1500 行）**：`alexgo-server/cmd` 入口、`pkg/resp`、`pkg/errors`、`pkg/auth`、`pkg/tenant`、`pkg/middleware`、`pkg/limiter` 等核心底座——展示"这是个什么系统"。
- **后 30 页（~1500 行）**：`modules/system` 的 controller/service 代表文件 + `frontend/admin` 的登录页、布局、用户管理页等 `.vue/.ts`——展示"后台管理端"。

清单以**实际行数为准**生成后打印统计表（每文件行数、累计页数），人工可审计；行数不够就从同一优先级池顺位补文件，超了就截断到整页边界（截断处标注 `... (文件续略)`）。

### 6.3 排除规则

- `*_test.go`、`*_mock*`、`node_modules`、`dist`、`.d.ts` 自动生成物。
- 含真实密钥/DSN 的配置文件（`configs/config.yaml`）**不进**源码文档——虽已知是本地默认值，仍避免任何凭据字样进申请材料。
- 单文件超长（>600 行）只取开头到整页边界并标注续略。

## 7. 操作手册设计

### 7.1 结构（目标 ≥25 页）

1. **软件概述**：定位（模块化单体后台基座）、功能清单表、技术架构简图（文字版）。
2. **运行环境**：Go 1.25 / MySQL 8 / Node 22 / 可选 Redis、NATS；硬件无特殊要求。
3. **安装与启动**：后端 `make migrate && make run`、前端 `pnpm install && pnpm dev`（含验证命令 `curl /health`）。
4. **通用功能**：登录/登出、密码修改、个人中心、消息通知、界面布局说明。
5. **功能模块操作**（每模块：进入路径 → 截图 → 操作步骤 → 关键字段说明）：
   - 仪表盘
   - 系统管理：用户、角色、菜单、部门、岗位、字典、配置、公告通知（含附件上传=文件能力展示）、租户、登录日志、操作日志、在线用户（含内嵌会员搜索=会员能力展示）
   - OAuth2 客户端管理、社交应用
   - 订单管理
   - 基础设施：代码生成
   - 注：会员/文件**无独立页面**，能力分别并入在线用户、公告附件两节展示（§3 已裁决，不补建页面）
6. **常见问题**：端口占用、DB 连不上、前端登录 401 等 3~5 条。

### 7.2 截图方案

- 起后端（`:8080`）+ admin dev（`:5666`），用 Playwright MCP 逐页实拍。
- **拍前处理**：停用（或从 admin 角色解绑）scorecard、fishgame 两个菜单目录——种子迁移会把它们绑进侧边栏，与"不进册"口径抵触；**拍完恢复并校验**（菜单数、绑定数与拍前一致）。
- 截图清单从第 5 章目录反推，预计 25~35 张，统一 1440×900 视口，登录态由 `admin/admin123` 自动登录获得。
- 每图配：图题（图 N）、进入路径、操作步骤。截图存 `docs/copyright/screenshots/`，PNG。
- 若本机起服务受阻（端口/DB），降级方案：先生成手册文字稿 + 截图占位符，截图补拍后重跑 `gen_manual.py`——不影响其他材料推进。

### 7.3 生成

- 正文以结构化 Python 数据（或 Markdown）描述章节；`gen_manual.py` 用 python-docx 渲染：标题层级、编号、表格、图片、页眉（与源码文档同款页眉）。

## 10. 风险与开放项

| 风险 | 缓解 |
|---|---|
| 本机 MySQL/端口导致服务起不来，截图受阻 | 手册文字稿先行，截图占位，补拍后重跑（§7.2） |
