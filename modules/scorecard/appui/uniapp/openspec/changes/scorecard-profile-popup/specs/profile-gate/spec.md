# profile-gate

## Purpose

统一打牌记账的用户资料（头像+昵称）弹框交互：开房前资料硬门、牌局内资料编辑、进局默认资料软提醒共用同一弹框，保证头像与昵称在所有入口可改、默认资料用户在进局时被轻提醒。

## ADDED Requirements

### Requirement: 统一资料弹框交互

系统 SHALL 提供统一的「完善资料」弹框（头像 + 昵称），在开房、进局提醒、牌局内编辑三处复用，并按模式呈现不同的关闭与按钮行为：

- gate（开房硬门）：提供「取消」与「保存并开房」；保存成功后继续开房动作，取消或点击关闭图标后留在当前页且不触发开房。
- reminder（进局软提醒）：不显示关闭图标，点击遮罩不得关闭，仅提供一个视觉弱化的「跳过」文本按钮；保存或跳过均继续原进局动作。
- edit（牌局内编辑）：提供「取消」与「保存」；保存成功后关闭弹框并刷新已展示的昵称头像。

弹框 SHALL 在微信小程序端使用官方头像选择能力（open-type=chooseAvatar）与昵称快捷填充能力（type=nickname），在 H5 端使用图片选择 + 普通文本输入；两端交互语义一致。

#### Scenario: 开房硬门行为保持

- **WHEN** 用户资料不完整（昵称为占位昵称或头像为空）且点击开房
- **THEN** 弹出 gate 模式弹框；点「取消」或关闭图标留在首页且不开房；点「保存并开房」且保存成功后自动完成开房

#### Scenario: 软提醒无其他关闭途径

- **WHEN** reminder 模式弹框弹出后，用户点击遮罩或寻找关闭图标
- **THEN** 弹框不关闭，页面上唯一可关闭途径是「跳过」按钮；「跳过」按钮字号与颜色视觉弱化、不易引起注意

#### Scenario: 双端输入方式

- **WHEN** 用户在微信小程序端点击头像区域或聚焦昵称输入框
- **THEN** 触发微信原生头像选择与昵称快捷填充；在 H5 端同一操作分别触发图片选择与普通文本输入

### Requirement: 进局默认资料软提醒

系统 SHALL 在用户进入牌局（房号/扫码进房、小程序码 scene 进房、登录后 scene 进房、冷启动回房）时检查资料：若昵称为占位昵称（微信用户xxxx / 用户xxxx 模式）或头像为空，先弹 reminder 模式提醒；用户保存成功或点「跳过」后继续原进局动作。资料完整的用户 SHALL 不弹窗、直接进局。用户未登录时 SHALL 先走原有登录流程，不弹资料提醒。

#### Scenario: 默认资料用户进房被提醒

- **WHEN** 资料为默认（占位昵称或空头像）的已登录用户通过房号/扫码、scene 或冷启动回房进入牌局
- **THEN** 先弹 reminder 弹框；点「跳过」后正常进局；改完资料保存后资料已更新且正常进局

#### Scenario: 登录后 scene 进房被提醒

- **WHEN** 未登录用户经小程序码进入、在登录页完成登录后携带进房场景
- **THEN** 登录成功后先弹 reminder 弹框，保存或跳过后进原目标房，且该房只进一次

#### Scenario: 资料完整用户不被打扰

- **WHEN** 资料完整的已登录用户走上述任一进局路径
- **THEN** 不出现任何资料弹框，直接进局

#### Scenario: 回房遇房已结束

- **WHEN** 冷启动回房时资料为默认，用户点「跳过」后（或保存后）发现原房间已结束
- **THEN** 按现状清理本地房间 id 并留在首页，弹框不阻断该清理流程

### Requirement: 牌局内资料编辑复用统一弹框

牌局内「修改昵称」入口 SHALL 打开与开房同款的统一资料弹框（edit 模式），用户可同时修改头像与昵称；保存成功后关闭弹框，房间成员与首页展示的昵称头像即时可见新值。原「只改昵称」的内嵌小输入层 SHALL 移除。

#### Scenario: 局内改头像与昵称

- **WHEN** 用户在牌局内打开「修改昵称」入口，更换头像并修改昵称后点「保存」
- **THEN** 保存成功、弹框关闭，牌桌上该用户的昵称与头像立即刷新为新值；「取消」则弹框关闭且资料不变

#### Scenario: 保存失败留在弹框

- **WHEN** edit 模式下保存接口失败（网络或服务端错误）
- **THEN** toast 提示错误、弹框保持打开，用户可重试或取消
