# room-create Delta Spec

## Purpose

开房入口（POST /api/app/scorecard/rooms）的行为契约：用户已有进行中牌局时开房返回该局而非报错，前端顺势进入；无局时正常创建。同时明确与进房（Join）一人一局拦截的边界。

## ADDED Requirements

### Requirement: 已有进行中牌局时开房返回该局

开房接口 SHALL 在请求者已有进行中牌局（本人为成员且房 status=进行中）时，返回 HTTP 200 与该局的房间快照（信封 data 与新建成功同构，字段为既有局的真实房况），而非报错。此时 SHALL NOT 创建新房间、SHALL NOT 产生新房间流水。

#### Scenario: 有进行中牌局时开房返回既有局

- **WHEN** 用户已在进行中牌局 A 中调用开房接口
- **THEN** 返回 200，data 为局 A 的房间快照（id、room_code 均为 A），不创建新房间

#### Scenario: 响应与新建成功同构

- **WHEN** 用户已有进行中牌局并调用开房接口
- **THEN** 响应信封与成功新建房间完全一致（code=0，data 为 RoomSnapshot），前端无需区分两种情形即可进入该局

### Requirement: 复用分支忽略开房入参

返回已有局时，请求携带的开房配置（茶饭百分比、茶饭目标、最大累计、自定义房号等）SHALL 被忽略，以既有局的房况为准。

#### Scenario: 自定义房号入参被忽略

- **WHEN** 用户已有进行中牌局 A，开房请求指定自定义房号 B
- **THEN** 返回局 A 的快照（房号为 A），不因房号 B 被占或入参配置产生额外错误

### Requirement: 无进行中牌局时正常创建

开房接口 SHALL 在请求者无进行中牌局时保持既有创建行为：按入参或服务端生成房号创建房间，返回新局快照；自定义房号被占仍返回 30106。

#### Scenario: 无局开房创建新局

- **WHEN** 用户没有任何进行中牌局并调用开房接口
- **THEN** 创建新房间并返回 200 与新局快照（既有创建行为不变）

### Requirement: 进房拦截保持不变

进房接口（join）SHALL 在请求者已有进行中牌局且目标为其不所属的另一局时，保持返回 30114「你还在其他牌局中，请先退出」；同房重进 SHALL 幂等返回现状不受影响。本变更仅作用于开房路径。

#### Scenario: 有局时进他房仍被拦截

- **WHEN** 用户已在进行中牌局 A 中按房号进入另一局 B
- **THEN** 返回 30114，不返回局 A 快照、不进入局 B
