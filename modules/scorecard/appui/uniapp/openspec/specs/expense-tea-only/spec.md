# expense-tea-only Specification

## Purpose
支出页在手动 DIY 茶档模式下支持「只记茶水不记分数」：付茶人扣分进茶饭池、无分数转移，流水以独立茶水行展示。

## Requirements

### Requirement: 茶水可单独提交（只记茶不记分）

手动 DIY 茶档模式（未开自动抽茶）下，支出页 SHALL 允许分数为 0、茶水金额大于 0 的提交：不要求选分数、不要求选记分对象；提交后仅茶水来源扣 T 进茶饭池，不产生任何分数转移与累计输分变化。分数大于 0 时 SHALL 保持现状：必须选记分对象。自动抽茶模式下 SHALL 保持现状：必须选分数才能提交（无单独记茶路径）。

#### Scenario: 只记茶提交成功

- **WHEN** 手动茶档模式下用户分数为 0、茶水金额大于 0，点提交
- **THEN** 提交成功：茶水来源扣 T、茶饭池 +T、各成员分数除茶水来源外无变化；返回房间页看到新流水

#### Scenario: 只记茶不要求选人

- **WHEN** 手动茶档模式下分数为 0 且未选记分对象，茶水金额大于 0
- **THEN** 可正常提交，不出现「请先选择记分对象」拦截

#### Scenario: 记分仍须选人

- **WHEN** 分数大于 0 但未选记分对象
- **THEN** 提交被拦截并提示先选记分对象（现状不变）

#### Scenario: 自动抽茶模式无单独记茶

- **WHEN** 自动抽茶模式下分数为 0（无论茶水档位是否被展示）
- **THEN** 提交不可用或被拦截，需先选分数（现状不变）

### Requirement: 茶水流水独立展示

type=1 流水中 score=0、tea>0 的记录 SHALL 展示为「付茶人 茶饭 −T 入池」语义的独立行（不画「A −0 → B +0」分数转移结构），茶水金额以茶色（jade）强调；score 大于 0 的记分行 SHALL 保持现状展示（分数转移 + 附茶标签）。房间页账板与流水分页弹层 SHALL 同时生效。

#### Scenario: 账板显示纯茶水行

- **WHEN** 房间页账板或全部流水弹层中出现 score=0、tea>0 的流水
- **THEN** 该行显示为「A 茶饭 −T 入池」样式，无记分对象与转移箭头

#### Scenario: 记分附茶展示不变

- **WHEN** 流水中存在 score 大于 0 且 tea 大于 0 的记分流水
- **THEN** 展示与现状一致：「A −S → B +S」附茶标签与茶色金额

### Requirement: 只记茶的服务端校验

记账服务 SHALL 在 score=0 且 tea 大于 0（手动模式）时接受请求：to_user_id 允许为 0，校验茶水来源在房后仅执行扣茶入池；SHALL 拒绝 score=0 且 tea=0、tea 超上限、茶水来源非房内成员（沿用既有错误码）。score 大于 0 的全部既有校验与记账语义 SHALL 不变。

#### Scenario: 只记茶通过校验

- **WHEN** 客户端提交 score=0、tea=T>0、to_user_id=0、tea_from 为房内成员的记账请求
- **THEN** 记账成功：来源扣 T、池 +T、总分守恒，返回最新快照与流水号

#### Scenario: 空请求仍被拒

- **WHEN** 客户端提交 score=0 且 tea=0 的记账请求
- **THEN** 服务端以参数错误拒绝，不产生任何账目变化

#### Scenario: 来源非房内成员被拒

- **WHEN** 只记茶请求的茶水来源用户不在房内
- **THEN** 服务端以既有非成员错误码拒绝，池与分数均不变
